# 028 test/card-overlap — 구현 문서

## 요약

카드 테스트의 가짜 2D 컨텍스트가 도형(`arc`·`moveTo`·`lineTo`·`arcTo` 경로를 `stroke`·`fill`한 것)의 경계 상자를 기록한다. 이걸로 16타입 × ko/en과 최악 조합 두 가지에서 원형 파형 고리·원 견본이 모든 글자와, 그리고 서로 24px 넘게 떨어지는지, 나머지 도형(초상 테두리·축 막대·자리표시 초상 안 고리)이 글자와 겹치지 않는지 테스트한다. 배치(`renderCard.ts`)는 바꾸지 않았다.

## 변경 파일

| 파일 | 내용 |

| `src/features/export/renderCard.test.ts` | 가짜 컨텍스트에 경로 기록(`ShapeCall`: 종류·`stroke`/`fill`·상자·clip 안 여부), `lineWidth`·clip을 `save`/`restore`로 되돌림, 글자에 글꼴 크기(`size`) 기록. 도우미 `crowdedView`·`fullRing`·`textBox`·`gapBetween`·`spacingProblems`, 상수 `MIN_GAP = 24`. 테스트 5개 추가 |

### 추가한 테스트

`describe('drawCard 도형과 글자 간격 (028)')`

1. 가짜 컨텍스트 자체: 원 채우기, 굵기 4 선 긋기, clip 안의 둥근 사각형 채우기·선 긋기, `restore` 뒤 선 긋기가 기대한 상자·종류·clip 표시로 기록되고, `restore`가 선 굵기와 clip을 되돌린다
2. 16타입 × ko, 3. 16타입 × en: 고리를 가장 크게(`signature`를 모두 1로) 해서 `spacingProblems`가 빈 배열
4. 최악 조합(향 이름 2줄 폭 한도까지), 5. 최악 조합(향 이름 1줄): 한도가 실제로 찼는지(이름 2줄, 계절 이름 말줄임 1줄, 향 이름 줄 수) 확인하고 `spacingProblems`가 빈 배열

`spacingProblems`는 어긋난 것을 `ring – "글자" 19.7px`처럼 문장으로 모아 돌려준다. 실패하면 어느 글자와 몇 px인지 바로 보인다. 단언 수를 줄이려고(도형 수백 개 × 글자 수십 개) 개별 `expect` 대신 목록 하나를 빈 배열과 비교한다.

## 알려진 한계

- 고리는 막대 180개를 합친 상자(원의 외접 사각형)로 본다. 상자 모서리 쪽은 실제로 비어 있으므로, 앞으로 글자를 고리 대각선 방향 가까이 두는 배치는 실제로 안 겹쳐도 실패할 수 있다. 그때는 막대별 상자로 바꾼다
- 글자 폭은 어림(한글 1em, 그 밖 0.58em)이다. 실제보다 넓어 보수적이지만, 특정 글자(W, M 등)는 실제가 어림보다 넓을 수 있다
