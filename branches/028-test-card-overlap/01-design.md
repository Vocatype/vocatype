# 028 test/card-overlap — 설계 문서

## 배경

027(퍼스널 컬러 공유 카드) 1차 리뷰 #2: 카드 테스트의 가짜 2D 컨텍스트는 `fillText`만 기록하고 `arc`·`moveTo`·`lineTo`는 아무것도 하지 않는다. 그래서 원형 파형 고리나 퍼스널 컬러 원 견본이 글자와 겹치도록 배치가 바뀌어도 `npm test`는 통과한다. 027에서는 리뷰어의 임시 탐침으로 겹침 0건을 확인하고(고리–원 견본 약 29.7px, 최악 조합 마지막 줄 y 1728, 한도 1740) 테스트는 후속으로 넘겼다.

## 목표

가짜 컨텍스트가 도형의 범위(경계 상자)를 기록하게 하고, 16타입 × ko/en과 최악 조합에서 고리·원 견본이 글자와 겹치지 않고 서로도 떨어져 있는지 테스트로 고정한다. 리뷰 탐침이 하던 확인을 `npm test`가 대신한다.

## 범위

### 포함

`src/features/export/renderCard.test.ts`만 바꾼다. `renderCard.ts`(배치)는 건드리지 않는다.

1. 가짜 컨텍스트가 경로를 기록한다
   - `beginPath`로 새 경로를 열고, `moveTo`·`lineTo`는 점, `arc`는 원 전체 상자(중심 ± 반지름), `arcTo`는 두 제어점을 넣는다(둥근 사각형은 네 모서리를 지나므로 사각형 전체가 된다)
   - `stroke`·`fill` 때 그 경로의 경계 상자를 도형 하나로 남긴다. `stroke`는 선 굵기의 절반만큼 사방으로 넓힌다(둥근 끝도 이 안에 든다)
   - 도형 종류: `arcTo`가 있으면 둥근 사각형, `arc`가 있으면 원, 둘 다 없으면 선
   - `clip` 뒤(그 `save`가 `restore`될 때까지)에 그린 도형은 잘림 표시를 단다. 자리표시 초상 안의 작은 고리와 카드 고리를 가르는 데 쓴다. `save`·`restore`는 선 굵기도 되돌린다(실제 캔버스와 같이)
   - `fillRect`(바탕·아우라)와 `drawImage`(초상)는 기록하지 않는다. 글자 뒤에 깔리는 것이 의도다
2. 글자에도 상자를 준다: 가로는 지금처럼 정렬과 어림 폭, 세로는 기준선 위 1.0em, 아래 0.25em
3. 새 테스트
   - 가짜 컨텍스트 자체 확인: `arc` 채우기, 선 굵기가 있는 선 긋기, `clip` 안의 도형이 기대한 상자·종류·잘림 표시로 기록된다
   - 16타입 × ko/en: 고리(잘리지 않은 선 180개, `SIGNATURE_BINS`)와 원 견본(잘리지 않은 원 채우기 5개)이 모든 글자와 24px 이상 떨어지고, 고리와 각 원 견본도 24px 이상 떨어진다. 나머지 도형(초상 테두리, 축 막대)은 글자와 겹치지 않는다
   - 최악 조합 두 가지: 027 예산 테스트의 조합(이름 2줄, 긴 캡션, 향 이름 2줄, 긴 궁합 이름)에 긴 계절 이름(1줄 한도까지 차서 원 견본에 가장 가깝다)을 더한 것과, 같은 조합에서 향 이름만 1줄인 경우(고리가 가장 위로 올라가 원 견본과 가장 가깝다)
   - 고리는 포락선을 평평하게 줘서 모든 막대가 바깥 반지름까지 닿게 한다. 실제 녹음 모양에 따라 고리 상자가 작아지면 겹침을 놓치므로, 가장 큰 고리로 검사한다

### 제외

- 카드 배치 변경. 테스트가 지금 배치에서 겹침을 찾으면 그때 따로 판단한다(설계 시점 계산으로는 겹침 없음)
- 글자끼리의 겹침. 027 테스트가 줄 위치·궁합 이름과 라벨의 가로 겹침을 이미 본다
- 실제 캔버스·글꼴로 그린 픽셀 비교(테스트 환경이 `node`이고 의존성을 늘리지 않는다)

## 결정과 근거

| 결정 | 근거 |
| --- | --- |
| 글자 상자 세로: 위 1.0em, 아래 0.25em | 이 저장소의 글꼴 목록(`-apple-system` … `Apple SD Gothic Neo` …)으로 내장 브라우저(macOS)에서 `measureText`를 잰 값: 글꼴 상자 위 0.958~0.976em, 아래 0.200~0.222em, 실제 글리프(『』·Á·g·j 포함) 위 최대 0.924em, 아래 최대 0.182em. 이보다 조금 넉넉하게 잡아 실제보다 겹침을 먼저 잡는다 |
| 글자 폭은 지금 어림(한글 1em, 그 밖 0.58em) 유지 | 같은 측정에서 실제 폭이 어림보다 좁다(36px "Polar opposite" 실제 218.8 / 어림 292, "최고의 짝" 132.3 / 165). 어림이 넉넉하므로 가로 간격도 실제보다 작게 나와 보수적이다 |
| 최소 간격 24px | 지금 배치가 일부러 둔 가장 좁은 간격이 계절 이름–원 견본 24px(`swatchLeft − 24`)이다. 1차 리뷰 #4에서 붙어 보인다고 넓힌 고리–원 견본 19.7px → 약 29.7px이 다시 좁아지면 이 기준에서 실패한다 |
| 고리는 상자 하나로 본다 | 막대 180개를 합친 상자(=원의 외접 사각형)는 원보다 크므로 보수적이다. 지금 배치는 상자 기준으로도 떨어져 있다(아래 계산) |
| 간격은 두 상자 사이 거리 | 가로·세로로 떨어진 만큼(`dx`, `dy`, 겹치면 0)의 `hypot`. 둘 다 0이면 겹침 |

### 설계 시점 계산(지금 배치, 위 상자 기준)

계절 이름 기준선을 `c`라 하면 원 견본은 중심 높이 `c − 16`, 반지름 30이고 오른쪽 끝이 카드 오른쪽 여백(1008)에 맞는다. 고리는 중심 x 898, 반지름 110, 막대 굵기 2.6이다.

| 쌍 | 간격 |
| --- | --- |
| 고리 윗변 – 원 견본 아랫변(향 이름 1줄) | 향 제목 `c + 134`, 고리 중심 `c + 155` → (c + 155 − 111.3) − (c + 14) = **29.7** |
| 고리 – 원 견본(향 이름 2줄) | 고리 중심이 27 내려가 56.7 |
| 고리 왼변 – 향 이름 오른쪽 끝 | 향 이름 폭 한도가 고리 왼쪽 30px 앞 → 30 − 1.3 = **28.7** |
| 고리 아랫변 – 궁합 이름(36px) 윗변 | 궁합 첫 줄 = 고리 중심 + 174 → 174 − 36 − 111.3 = **26.7** |
| 계절 이름 오른쪽 끝 – 원 견본 왼변 | 폭 한도가 견본 왼쪽 24px 앞 → **24** |

가장 좁은 곳이 24px이라 기준을 넘는다.
