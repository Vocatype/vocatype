# 016 test/result-screen-render — 구현 문서

## 요약

`ResultScreen`을 `react-dom/server`의 `renderToStaticMarkup`으로 렌더하는 테스트 12개를 추가했다(테스트 파일 28 → 29, 테스트 181 → 193). DOM 라이브러리를 들이지 않고 Vitest `node` 환경을 유지했으며, 구현 코드는 바꾸지 않았다.
설계의 회귀 감지(meter 눈금)에 더해 영어 소문자·머리글 길이 출처·저장 버튼 제거 회귀를 일부러 넣어 테스트가 실패하는지 확인했다. 1차·2차 리뷰(03 문서) 반영분이 들어 있다.

## 설계 대비 달라진 점

| 설계 | 구현 | 이유 |
| --- | --- | --- |
| 헬퍼 `openingTags`·`textOf` | + `escape`(React 이스케이프 `& < > " '`)와 `meters` | 카탈로그 문구·리딩에 `'`나 `"`가 들어가도 `toContain` 비교가 깨지지 않게 기대값을 마크업과 같은 형태로 맞춘다. 지금의 ko/en 문구에는 해당 문자가 없어 예방용이며, 1차 리뷰 #4로 React 렌더 결과와 대조하는 테스트를 붙였다 |
| 기대 문구를 사전 문자열의 `{other}` 치환으로 | `formatMessage(messages[locale][key], params)`를 직접 호출 | 치환 규칙을 테스트가 다시 구현하지 않고, 사전·치환이 바뀌어도 의도("화면 문구와 같다")가 유지된다 |

## 알려진 한계

- 정적 렌더라 효과(`useEffect`)·상태 변화(저장 중/저장됨 문구, 공유 버튼 표시)는 검사하지 않는다. 그 부분은 캔버스와 `navigator.share`가 필요해 브라우저 확인으로 남는다.
- `aria-labelledby`(섹션 ↔ 제목 id) 연결, 면책 문구, 저장 상태 문구 내용은 설계 범위 밖이라 검사하지 않는다(리뷰어의 회귀 시도에서 통과한 항목). 필요해지면 같은 헬퍼로 추가할 수 있다.
- 속성 파싱은 `name="value"` 형태의 열림 태그만 다룬다. React의 정적 마크업은 항상 이 형태라 충분하지만, 다른 렌더러의 출력에는 쓸 수 없다.
