# branches/ — 작업 단위 문서

모든 작업은 번호가 붙은 브랜치 하나로 진행하고, 그 브랜치의 설계·구현·리뷰 문서를 이 폴더에 남긴다.
문서는 브랜치와 함께 main에 병합되어 이력이 된다.

## 규칙

| 항목 | 규칙 | 예시 |
| --- | --- | --- |
| git 브랜치 이름 | `<type>/<번호>-<이름>` | `feature/002-ui-main` |
| 문서 폴더 | `branches/<번호>-<type>-<이름>/` | `branches/002-feature-ui-main/` |
| 번호 | 001부터 999까지 세 자리, 작업 순서대로 증가 | `001`, `002`, … |
| type | `feature`, `fix`, `refactor`, `chore`, `docs`, `test`, `perf` | |
| 커밋 메시지 | Conventional Commits (`type(scope): 요약`) | `feat(record): 녹음 화면 추가` |
| 병합 | `git merge --no-ff`로 병합 커밋을 남기고 브랜치 삭제 | |

## 폴더 안의 문서

1. `01-design.md` — 설계 문서. 목표, 범위, 구조, 결정 사항과 근거, 검증 계획.
2. `02-implementation.md` — 구현 문서. 변경 파일, 주요 구현 내용, 설계 대비 달라진 점, 검증 결과.
3. `03-review.md` — 리뷰 문서. 차수(1차, 2차, …)별 체크리스트, 발견 사항, 조치, 결론.

## 흐름

```
main ──┬── 브랜치 생성 ── 설계 문서 ── 구현 ── 구현 문서 ── 리뷰(n차) ── 리뷰 문서 ──┐
       │                                        └─ 문제 발견 시 수정 후 다음 차수 ─┘   │
       └──────────────────────────── --no-ff 병합, 브랜치 삭제 ◀────────────────────┘
```

리뷰에서 "병합 가능" 결론이 나오기 전에는 main에 병합하지 않는다.
