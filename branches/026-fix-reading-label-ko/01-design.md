# 026 fix/reading-label-ko — 설계 문서

## 변경 사유

사용자 요청(2026-10-22): 결과 화면의 "목소리 리딩"이라는 말이 무슨 뜻인지 와닿지 않는다. AI가 6축 점수를 보고 쓰는 해설 글이므로 **"목소리 해설"**로 바꾼다.

## 범위

### 포함

- `src/i18n/messages/ko.ts`: `result.section.reading` "목소리 리딩" → "목소리 해설". 화면에 보이는 한국어 중 "리딩"이 들어간 문구는 이것 하나다(저장소 검색으로 확인)
- `README.md`: 기능을 소개하는 문장(첫 소개, 개인정보 원칙, 텍스트 제공자 절 제목·첫 문장, 알려진 한계)의 "목소리 리딩"을 "목소리 해설"로. 텍스트 제공자 절에 "코드·API에서는 `reading`(리딩)이라는 이름을 그대로 쓴다"는 용어 안내 한 줄

### 제외

- 코드 식별자(`reading`, `/api/reading`, `ReadingResponse`, `READING_*`), 코드 주석, 테스트 이름, `branches/` 과거 문서: 내부 용어라 그대로 둔다. 바꾸면 API 계약과 문서 이력까지 흔들린다
- 영어 문구("Voice reading"): 영어에서는 해석·감상이라는 뜻으로 자연스럽고, 사용자가 요청한 것은 한국어 표현이다
- AI 프롬프트(영어 "voice reading"): 화면에 보이지 않는다
- 저장 이미지 카드: 이 제목을 그리지 않는다(캡션 한 줄만 그림, `renderCard.ts`)

1. typecheck / lint / test / build 종료 코드 0

3. 빌드된 JS 번들에 "목소리 해설"이 있고 "목소리 리딩"이 없는지
