설정 한 줄, 생성 타입 복원, 모델 상수·토큰 상한 두 줄, 테스트 기대값, README 수치의 작은 변경이라 별도 리뷰 에이전트를 쓰지 않고 구현자가 diff(`main..chore/011-enable-claude-chain`)와 실측 기록을 점검했다.

| 항목 | 결과 |
| --- | --- |
| 변경 범위가 설계와 같은가 | 설계의 포함 항목(체인 설정, 타입 재생성, 모델 상수 교체 가능성, README)만. 추가는 `MAX_TOKENS` 512 하나이며 02 문서에 근거 기록 |
| 키 흐름 | 키 값은 사용자가 `wrangler secret put`으로 직접 넣었고 에이전트·채팅·저장소를 거치지 않음. `git grep -i sk-ant`는 테스트 자리표시뿐. `.dev.vars`는 수정하지 않음 |
| 생성 타입 파일 | `AI_PROVIDER`·`TEXT_PROVIDER` 리터럴, `ANTHROPIC_API_KEY` 없음. 012가 넓어진 채로 커밋한 것도 바로잡혔다. 주의: 로컬에서 `npm run cf-typegen`을 다시 돌리면 `.dev.vars` 때문에 또 넓어지므로 커밋 전 확인 필요(README·010 문서에 이미 있는 절차) |
| 모델 교체 근거 | 같은 프롬프트·파서로 3개 모델 ko/en 실측. 3.3 70B 영어 2/2 폭주(27~30초, 체인 예산 초과)는 재현됐고, Scout 8/8 통과. Qwen3는 사고 토큰으로 잘림. 선택은 실측 표로 뒷받침됨 |

| 체인 보호 장치 | 속도 제한(IP당 1분 5회)·교차 사이트 403·1KB 413·25초 예산 모두 코드 변경 없음. Claude는 앞 제공자 실패 시에만 호출 |
| README 정합성 | 모델 이름 세 곳, 뉴런 수치, "Claude 추가하기" 절차(`--name` 없이 맞음), 설정 표와 일치 |
| 테스트 | 운영 모델 이름과 `max_tokens`를 테스트가 단언. 기존 체인·파서 테스트 변경 없음. 28 파일 181 통과 |
| 개인정보 흐름 | 변화 없음(타입 코드·여섯 축·언어만 서버로, 제공자에는 서버가 만든 프롬프트만) |
| 검증 명령 | typecheck / lint / test / build 통과, 빌드본 workerd에서 `/api/config`·ko/en 리딩 확인 |
