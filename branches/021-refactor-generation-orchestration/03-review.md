# 021 refactor/generation-orchestration — 리뷰 문서

리뷰 대상: `refactor/021-generation-orchestration` → `main` 전체 diff.
리뷰 방식: 별도 리뷰 에이전트(가벼운 모델)가 원본 화면(`git show main:src/screens/GeneratingScreen.tsx`)과 새 `generate.ts`·화면을 줄 단위로 대조했다. 검증 명령 4종은 종료 코드로 확인했고, 회귀를 일부러 넣어 테스트가 잡는지 실측했다. 반영은 구현자가 했다.

## 1차 리뷰

대상: `044307c`(설계·리팩터링·테스트 19개·구현 문서). 검증 명령 4종 종료 코드 0(30 파일 212 테스트, main은 29 파일 193 테스트).
새 테스트 파일은 단독 5회, CPU 부하(load average 19)에서 25회, `TZ=America/Los_Angeles LANG=C`에서 모두 통과했다.

### 원본과의 동작 비교

리뷰어는 원본 `useEffect`의 `run`과 새 화면의 `run`(+`runGeneration`)을 그대로 옮긴 임시 비교 테스트를 만들었다. 두 쪽에 같은 사건 순서를 넣고 결과를 비교했다.

- 사건: 분석 종료, 설정 응답, 초상 응답, 리딩 응답, 취소, 화면 언어 변경, 초상·리딩 실패. 이들의 모든 순열에 기능 4조합, low-signal, 분석 실패를 곱했다.
- 비교한 것: 진행 이벤트, `onGenerated` 인자, `setFailed`, fetch 순서와 본문, 분석 인자, 요청 신호의 취소 여부, 정리 뒤 이벤트, unhandled rejection.

결과는 3,777건 + 실패 응답 978건에서 불일치 0건, unhandled rejection 0건이다.
비교 테스트가 민감한지도 확인했다. 단계 전환 조건을 바꾸면 48건, 초상이 성공할 때만 전환하게 바꾸면 108건에서 차이가 났다.
한계: React 렌더는 하지 않았고, 최소 표시 시간은 4ms로 줄였으며, fetch는 스텁이다. 비교 테스트는 지운 뒤 작업 트리가 깨끗함을 확인했다.

### 회귀 시도

구현 문서의 13건을 다시 돌려 같은 테스트가 실패함을 확인했다. 리뷰어가 따로 넣은 회귀는 다음과 같다.

- 잡힌 것(`generate.ts`): 리딩을 초상 뒤로 직렬화, 리딩 요청에 신호를 넘기지 않음, 취소 시 `undefined` 반환(3곳), 취소 시 `AbortError` 대신 일반 `Error`, 최종 취소 확인을 `Promise.all` 앞으로, 설정 뒤 취소 확인을 `onStage` 뒤로, 리딩 언어를 낭독 언어로, 초상 본문에 `features` 추가, 전환 조건에서 `wantReading` 제거, 첫 단계를 리딩 우선으로, 설정 조회를 분석 앞에서 직렬화, 단계 2회 호출.
- 놓친 것(`generate.ts`):
  - 초상이 성공(null 아님)일 때만 리딩으로 전환 → 아래 #2.
  - 분석에 다른 `AbortController`의 신호 전달 → 아래 #1.
  - 리딩 요청을 초상보다 먼저 전송: 같은 틱에 둘 다 나가므로 화면에서 구별되지 않는다. 조치하지 않는다.
- 놓친 것(화면 6건): `startedAt` 이동, `catch` 가드 제거, ×1.0, 표시 시간 뒤 취소 확인 제거, 0.9 변경, 시작 시점 언어값. 화면 테스트는 설계상 범위 밖이므로 아래 #4로 문서의 한계에 적는다.
