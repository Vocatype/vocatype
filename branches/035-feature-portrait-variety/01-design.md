# 035 feature/portrait-variety — 설계 문서

## 변경 사유

사용자 지적(2026-10-29): 같은 목소리 타입이면 초상이 너무 비슷하게 나온다.

원인: 초상 프롬프트(`buildPortraitPrompt`)는 타입 코드 4글자로만 만든다. 그래서 같은 타입이면 프롬프트가 글자 하나까지 같다. Workers AI 때는 씨앗(`seed`)이 얼굴을 갈랐지만, OpenAI(031)는 씨앗을 받지 않는다. 그 결과 모델이 가장 무난한 얼굴로 쏠린다.

사용자 결정(대화에서 정한 최종안):

1. **씨앗 연출 변주.** 녹음마다 붙는 씨앗(측정값 8개의 FNV-1a 해시, `seedFromFeatures`)으로, 서버가 각도·구도·배경·옷·머리·소품을 후보에서 하나씩 고른다. OpenAI에는 고른 단어만 가고 씨앗 숫자는 가지 않는다.
2. **축 수치를 그림 의미로.** 여섯 축 가운데 **음높이를 뺀 다섯 축**을, 소리의 뜻이 아니라 그림의 뜻(조명 색온도·색의 진하기·자세의 움직임·표정의 생기·화면 밝기)으로 바꿔 0~1 값과 0·1의 뜻을 함께 보낸다. "이 값으로 성별·나이·인종을 정하지 말 것"도 함께 적는다. 지금 타입으로 정하던 조명·자세·표정 문구는 이 값으로 대신한다.
3. **타입 영어 이름**(예: "The Fireside Storyteller")을 분위기 참고로 한 줄 넣는다. 그림에 글자로 넣지 말라고 적는다.
4. 성별·나이·인종은 지금처럼 지정하지 않는다.

## 범위

### 포함

- `worker/ai/portraitPrompt.ts`(새 파일): `buildPortraitPrompt({ typeCode, axes, seed })`, 후보 목록 `STAGING`, 그림 의미 축 `MOOD_AXES`, 씨앗에서 후보를 고르는 `pickFor`. 서버만 쓰므로 `shared/catalog.ts` 에서 옮긴다(해설 프롬프트 `readingPrompt.ts` 와 같은 자리)
- `shared/api.ts`: `PortraitRequest` 에 `axes`(해설과 같은 여섯 축, 0..1, 소수 둘째 자리). 본문 상한 주석
- `worker/portrait.ts`: `axes` 검증(해설 검증과 같은 함수를 함께 쓴다)
- `worker/reading.ts`: 축 검증을 `validateAxes` 로 떼어 내보낸다
- `worker/index.ts`: 새 프롬프트 함수 호출
- `src/features/ai/generate.ts`: 초상 요청에 반올림한 축(`toReadingAxes`)을 넣는다
- 테스트: 프롬프트(결정성·다양성·금지어·씨앗·타입 코드 비노출·음높이 제외·수치 형식), 검증, 라우트, 클라이언트
- `README.md`: 보내는 데이터(초상 요청에 여섯 축 추가, OpenAI에는 문장만)

### 제외

- 성별·나이·인종 지정(위 4)
- 결과 화면·공유 이미지 변경 없음
- Workers AI 초상 제공자는 같은 프롬프트를 쓰고 씨앗도 그대로 받는다

## 결정과 근거

| 결정 | 근거 |
| --- | --- |
| 후보 목록(각도 4·구도 3·배경 4·옷 5·머리 6·소품 3) | 4,320가지 조합. 머리 모양을 넓게 둬 성별을 정하지 않고도 외모가 갈린다. 옷 색은 지금처럼 퍼스널 컬러 |
| 항목마다 씨앗을 다르게 섞어 고름 | 같은 씨앗 비트를 나눠 쓰면 항목끼리 짝지어 움직인다. 항목 번호를 섞은 32비트 정수 해시로 고른다. 같은 녹음이면 언제나 같은 조합이다 |
| 음높이 제외 | 외모(성별·나이)와 가장 쉽게 연결되는 축이다. 해설은 결과 글을 검사할 수 있지만, 이미지는 결과를 검사할 수 없다 |
| 소리 뜻 대신 그림 뜻 | "낮고 따뜻한 음색" 같은 설명은 외모 추정으로 이어지기 쉽다 |
| 축 값은 0..1 소수 둘째 자리 그대로 | 클라이언트가 해설 요청에 이미 같은 값을 보낸다. 새로 나가는 정보는 아니다. 서버가 다시 반올림하고 범위를 검증한다 |
| 초상 요청에 축 필수 | 축이 없는 옛 클라이언트(배포 전에 열어 둔 탭)는 400 → 자리표시 초상으로 간다. 새로 고치면 된다 |
| 문장에 타입 코드·씨앗 숫자를 넣지 않음 | 모델이 의미 없는 글자를 그림에 넣거나 해석하지 않게 한다 |
